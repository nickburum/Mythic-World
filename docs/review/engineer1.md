## Findings (ordered by severity; max 10)
- [P0] Rewarded "Continue" never completes on device: the ad delegate is deallocated the moment it is assigned — /home/user/Mythic-World/ios/GameBox/AdsBridge.swift:51-55 — `GADRewardedAd.fullScreenContentDelegate` is a `weak` property and `AdDismissWatcher { … }` has no other owner, so `adDidDismissFullScreenContent` never fires, `onResult` never reaches JS, `await ads.show()` in src/extras.js:79 and skip/src/main.js:211 never resolves, the button stays `disabled`, `ads.pending` is stuck and `load()` is never re-issued (the one monetisation feature in the brief is dead). Fix: add `private var watcher: AdDismissWatcher?` to `AdsBridge`, set `self.watcher = AdDismissWatcher { [weak self] in self?.watcher = nil; … }` and `ad.fullScreenContentDelegate = watcher`; in src/ads.js:34 add a 60 s timeout that resolves `false` and resets `pending`.
- [P1] Challenge links shared from the iOS app are dead for everyone — /home/user/Mythic-World/src/challenge.js:72-77 and ios/GameBox/GameView.swift:62-68 — inside the shell `window.parent.location.href` is `gamebox://app/index.html`, so links become `gamebox://app/index.html#play=skip&c=…`: a friend without the app gets a URL nothing can open, and with the app `handle(deepLink:)` sees host `app`, builds `#play=app&play=skip&c=…`, box.js:31 matches `play=app`, `byId` returns null and nothing opens. Fix: in `challengeBase`, when `location.protocol` is not http(s) use a constant public base (e.g. `https://<pages-domain>/`); in `handle(deepLink:)` parse the fragment with `URLComponents` and accept `#play=<id>&c=…` on any host; add Associated Domains (APPLE-SETUP §10) before ship. Also box.js:80 (`hashchange`) calls `this.open(m[1])` without the `c=` payload — pass `location.hash.replace(/^#play=[a-z-]+&?/, '#')` as line 32 does.
- [P1] Deep-link handler injects raw URL text into JavaScript and loses cold-start links — /home/user/Mythic-World/ios/GameBox/GameView.swift:67 (`"location.hash = '\(hash)';"`; `url.fragment` is percent-decoded, so a crafted `gamebox://x/#');<js>//` link executes arbitrary JS with access to the cloud/gameCenter/ads bridges) and GameView.swift:8,58 (`PassthroughSubject` has no replay and `evaluateJavaScript` before `didFinish` runs against the still-loading document, so a link that launches the app is dropped). Fix: build the statement with `JSONSerialization` (`"location.hash = \(jsonEncodedHash);"`), keep `private var pendingLink: URL?`, implement `webView(_:didFinish:)` to flush it, and use `CurrentValueSubject<URL?, Never>` (or store on the VC) so a link delivered before `viewDidLoad` survives.
- [P1] "Reset all scores" is a no-op on iPhone and would be undone by iCloud anyway — /home/user/Mythic-World/src/box.js:74-76 — `confirm()` in a WKWebView with no `WKUIDelegate` (GameView.swift sets only `navigationDelegate`) returns `false` immediately, so the button does nothing; even when it runs, it only removes localStorage keys and never sends `{type:'remove'}` (CloudBridge.swift:23 supports it; src/cloud.js never emits it), so the next launch's `getAll` merge (cloud.js:17 returns `cloudRaw` when local is absent) restores every score and toasts "Scores restored from iCloud". Fix: replace `confirm` with an in-page two-tap confirm (or add a `WKUIDelegate` implementing `runJavaScriptConfirmPanelWithMessage`), add `Cloud.remove(keys)` that posts `remove` for every `SYNC_KEYS` entry and deletes them from `this.last`, and call it from the reset handler.
- [P1] Haptics only work in SKIP; the hub and the other four games call `navigator.vibrate`, which does not exist on iOS — /home/user/Mythic-World/src/box.js:12, melt/src/platform/haptics.js:5-9, sky-temple/src/platform/haptics.js:6-11, pop/src/main.js:10, orbit/src/main.js:8 — only skip/src/platform/haptics.js:6 posts to `webkit.messageHandlers.haptics`, so the Settings sheet's "Haptics — applies to every game" is false on the target platform and the brief's "haptic on every success" is unmet. Fix: promote skip's haptics.js to `src/haptics.js` (bridge first, `navigator.vibrate` fallback, `setEnabled`), import it from the hub and all five games, and have the hub call `setEnabled(settings.haptics)`.
- [P1] No recovery when WebKit's content process is killed — /home/user/Mythic-World/ios/GameBox/GameView.swift:13 — `webViewWebContentProcessDidTerminate` is not implemented; under memory pressure (five canvas games, backdrop blurs) or a WebContent crash the app shows a blank dark view until force-quit. Fix: `func webViewWebContentProcessDidTerminate(_ webView: WKWebView) { webView.load(URLRequest(url: URL(string: "gamebox://app/index.html")!)) }` (the hub rebuilds its state from localStorage on load, so this is cheap).
- [P1] Ads configuration is not release-ready — /home/user/Mythic-World/ios/GameBox/AdsBridge.swift:15 and ios/project.yml:56-57 — Google's public test unit/app IDs are hardcoded (a release with them earns nothing and is flagged as invalid traffic), there is no UMP consent flow (required by Google's EU User Consent Policy for EEA/UK impressions), and `NSUserTrackingUsageDescription` is declared while `ATTrackingManager.requestTrackingAuthorization` is never called, which makes the App Privacy "tracking" answer inconsistent (Guideline 5.1.2 risk). Fix: move both IDs to build settings (`#if DEBUG` test IDs, release IDs from an xcconfig/`INFOPLIST_KEY_GADApplicationIdentifier`), add the `GoogleUserMessagingPlatform` package and gather consent before `GADMobileAds.sharedInstance().start`, and either request ATT after the first session or configure non-personalised ads and answer "no tracking"; also fix ios/README.md:41-42, which still says "makes no network calls / answer No".
- [P2] Audio stays dead after a phone call, Siri or backgrounding — /home/user/Mythic-World/melt/src/audio/sfx.js:25, skip/src/audio/sfx.js:16, pop/src/main.js:14, orbit/src/main.js:20, sky-temple/src/audio/sfx.js:30 — every unlock path resumes only when `ctx.state === 'suspended'`, but iOS WebKit reports the non-standard `'interrupted'` state after an audio-session interruption, so `resume()` is never called and the generative music and SFX are silent until reload. Fix: `if (ctx.state !== 'running') ctx.resume()` in each `unlock()`, and call it on `visibilitychange` (when `!document.hidden`) and `pageshow`; same for `Music` (src/music.js:57).
- [P2] iCloud snapshot can clobber a running game and sound state leaks between hub and games — /home/user/Mythic-World/src/cloud.js:61,70 and src/box.js:16,69 — an external iCloud change writes merged keys into localStorage at any time while the iframe game holds `this.best` in memory (melt/src/main.js:51) and writes its lower value back on game over; `push()` then uploads that lower raw value unmerged, undoing the max-merge. Separately, muting inside a game writes `<id>.muted` but `gamebox.settings.sound` is never re-derived, so the hub icon and the next `applySettings` fan-out disagree. Fix: in `push()` send `mergeValue(k, l[k], this.last[k])` instead of `l[k]`; in `close()` re-read `melt.muted`/`skip.muted` etc. and update `this.settings.sound` + `syncSound()`.
- [P2] First-frame and per-frame polish on device — /home/user/Mythic-World/ios/project.yml:47 (`UILaunchScreen: {}` gives a white launch flash before the dark page, against the brief's "first frame carries the install") and css/box.css:53 (`backdrop-filter: blur(10px)` on the always-visible back pill sits over a 60 fps canvas iframe, forcing a per-frame blur on older iPhones). Fix: `UILaunchScreen: { UIColorName: LaunchBackground }` with a `#0b1020` colour set written to Assets.xcassets by ios/bootstrap.sh; drop the blur on `.back-pill` (solid `rgba(8,12,24,.75)` reads fine) or apply it only while `.player:not(.quiet)`.
