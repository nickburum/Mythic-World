## Findings (ordered by severity; max 12)
- [P1] **SKIP adds an extra game loop every time the app goes to the background and comes back.** — `skip/src/main.js` `onVisibility()` (l.134–137): when the page becomes visible it calls `requestAnimationFrame(frame)` again, but the frame request made before backgrounding is still waiting, so both run and both keep rescheduling. — Repro: in a SKIP run, fire hidden→visible 3 times (the frame request queued before hiding is still waiting, as on iOS). Calls to `frame()` went from 60/s to 240/s. Each app switch adds another full update and render per vsync, so after a few switches on a phone the game drops frames and heats up. — Fix: keep the rAF id and `cancelAnimationFrame` it before requesting a new frame, or use a `looping` flag so `frame()` only reschedules itself.
- [P1] **None of the five games pause when interrupted, and none has a "tap to resume" screen.** — MELT/POP/ORBIT/Sky Temple `visibilitychange` handlers only reset `this.last`. SKIP stops its loop but resumes immediately. `GameView.swift` does not forward resign-active. — Repro: start MELT or ORBIT and mark the page hidden for 1.5 s. Both carried on to game over while hidden (`playing→over`), and no game showed any pause UI. On a phone, pulling down Notification Centre or Control Center, or getting a call banner, does not hide the page, so the run keeps going and the tester dies. — Fix: shared `extras.pause()` with a "Tap to resume" overlay, triggered by `visibilitychange` hidden, `pagehide`, and a native `sceneWillResignActive` → `evaluateJavaScript("gamebox:pause")`.
- [P1] **One tap on "Reset all scores" can wipe every score while the button looks safe.** — `src/box.js` reset handler: the 4 s label-revert `setTimeout` is never cleared, and it does not clear `armed`. — Repro (verified): tap Reset, tap again at 3 s (scores reset), tap again at 3.5 s (re-armed). At 4 s the label goes back to "Reset all scores" with class `btn danger`, but the button is still armed. One more tap wiped `melt.best`. — Fix: `clearTimeout(this.resetT)` on every arm, and set `armed = 0` inside the same timeout that restores the label.
- [P1] **Web deploys reach players late or never: service-worker versions are bumped by hand and already missed.** — In d95059d, `css/box.css`, `src/box.js`, `src/cloud.js`, `src/music.js`, `src/extras.js` and the new `src/haptics.js` changed, but the hub `sw.js` is still `gamebox-v3`. Every worker is cache-first and never revalidates, so returning Pages users keep the old hub indefinitely. Shared `../src/*.js` and `../css/game-ui.css` are cached separately by each game's worker, and `caches.match` searches every cache. — Repro (verified): deploy a change to `src/extras.js` and bump the hub to v4. The hub picks up its new `box.js`, but POP in the box still serves the old `extras.js`. The hub ASSETS list also omits `src/haptics.js`, and `addAll(...).catch(()=>{})` hides precache failures. (iOS is unaffected; it doesn't register workers on `gamebox://`.) — Fix: `build-web.sh` writes a content hash into all six `sw.js` VERSIONs; use network-first or stale-while-revalidate for html/js/css; add a CI check that fails when shipped files change but the version doesn't.
- [P1] **The MELT, SKIP and Sky Temple workers delete every other game's offline cache.** — `melt/sw.js`, `skip/sw.js` and `sky-temple/sw.js` `activate`: `keys.filter(k => k !== VERSION)` (POP, ORBIT and the hub filter by prefix). — Repro (verified with `caches.keys()`): load the hub (`gamebox-v3`: 18 entries), then open MELT, leaving only `melt-v9`. Open POP then Sky Temple, leaving only `skytemple-v8` plus an empty `gamebox-v3`. Offline play of the other games and the hub breaks, and each game re-downloads. — Fix: `k.startsWith('melt-') && k !== VERSION` (and the same for each game).
- [P1] **CI never runs the shipping build and deploys raw repo files.** — `.github/workflows/deploy.yml` uploads `path: '.'`, which publishes `ios/`, `store/`, `tools/`, `tests/`, `docs/` and every `art/screens` PNG to Pages. `build-web.sh` and the six `--screens` smoke tests never run in CI. There is no iOS job, and the step name still says "MELT + SKIP + Sky Temple". — Fix: run `bash scripts/build-web.sh dist`, run `npm run screens:all` (Playwright) as a smoke gate on PRs, and `upload-pages-artifact path: dist`. Add a macOS job that runs `xcodegen` and `xcodebuild build` with no signing.
- [P1] **The TestFlight lane is likely to fail or ship a duplicate build.** — `ios/fastlane/Fastfile` with `ios/project.yml`:
  - `increment_build_number` uses agvtool, which needs `VERSIONING_SYSTEM: apple-generic`; `project.yml` doesn't set it.
  - `DEVELOPMENT_TEAM: ""`, so `build_app` has no team to sign with.
  - `bootstrap.sh` ends by running `open GameBox.xcodeproj`, which launches Xcode on every lane run.
  - SPM `GoogleMobileAds from: 11.0.0` has no committed `Package.resolved` and the project is regenerated each run, so native dependencies float.
  - The generated `ios/GameBox/web`, `GameBox.xcodeproj` and `Assets.xcassets` are not in `.gitignore`.
  
  — Fix: add `VERSIONING_SYSTEM: apple-generic` and set `CURRENT_PROJECT_VERSION` from the lane; require `--team` in CI; skip `open` when `$CI` is set; pin `exactVersion` and commit `Package.resolved`; gitignore the generated paths.
- [P2] **Double-tapping a game card loads the game twice.** — `src/box.js` grid click handler: a `setTimeout(open, 120)` per tap, with no guard. — Repro: tap a card twice 40 ms apart at 375×667. The iframe navigates to `skip/index.html?box=1` twice: the title and music restart and the tutorial check runs twice. — Fix: ignore clicks while an open is pending, and in `open()` return early if `this.current?.id === id` and the frame already points at it.
- [P2] **In landscape (web/PWA only; the iOS app is portrait-locked), Settings and SKIP's menu run off-screen.** — `css/box.css .sheet` and SKIP title CSS. — Repro: at 667×375 the settings sheet is 494 px tall with `overflow: visible`. The Sound toggle sits at y=−65 and Haptics at y=−3, so both are unreachable. SKIP's title "How to play", "Settings" and high score sit at y=384, below the bottom edge (also at 932×430). — Fix: `.sheet{max-height:calc(100dvh - 16px);overflow:auto}`, plus a landscape media query for SKIP's menu (or force a "rotate your phone" overlay in the web build).
- [P2] **The smoke tools can pass while testing the wrong copy of the code.** — `tools/render-hub.mjs` and each `render-art.mjs` hard-code ports 8086–8099 and treat "server ready" as `fetch(BASE).ok`. If another worktree's server already holds the port (likely with parallel reviewers), they test that tree and still print "smoke test: no page errors". Each `--screens` run also rewrites 29 committed PNGs, so every run produces a noisy diff. — Fix: bind port 0 or a random port, check a per-run token file before testing, and use a fixed seed and clock for screenshots (or stop committing `art/screens`).
- [P2] **The "meta progression core" from d95059d does nothing in the app.** — `src/meta.js` is copied into the build, but no runtime file imports it (only `tests/meta.test.js`). A TestFlight tester gets no progression. — Fix: wire it into `extras.onOver` and the hub, or leave it out of the build until it is.
- [P2] **On the web, Back after leaving a game does nothing.** — `src/box.js close()` uses `replaceState` after `open()` did `pushState`, which leaves two identical history entries. — Repro: open a game, tap "Games", then press browser Back. The URL and view stay the same, so the user has to press Back twice. — Fix: in `close()`, call `history.back()` when the current entry was pushed by `open()`.
